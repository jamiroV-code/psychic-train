Three directions for the interface

The app has five dashboards, no navigation, and no stylesheet of any kind. These are three genuinely different answers to what it should become — rendered, not described, so they can be compared rather than imagined.

PROPOSAL Nothing here is merged, and no application code has been changed. This page is a standalone mock-up committed alongside the audit. The real web/ routes are untouched and still render exactly as they did before — 193 unit tests, 55 end-to-end tests and tsc all pass on this branch, unchanged.
A

Terminal

Dark by default, monospaced numerals, as much on screen at once as will fit. Built for one person watching five dashboards on a large monitor all day. Uncertainty is compressed to a mark you learn to read at a glance.

C

Confidence-first

Not a third skin — a layer of meaning that sits on top of either A or B. Certainty stops being a footnote and becomes a column, a gutter, and a permanent strip across the top. This is the project's own stated purpose made visible: show how strong a read is, and where the signals disagree.

ALL

What all three share

These parts do not depend on which direction wins, and are the safest things to build first.

One validated colour palette, already in the repo

The on-chain dashboard's six chart colours are byte-identical to a reference palette that passes colour-blindness and legibility gates in both light and dark. The other two palettes in the app — in MindshareView and RelativePerformanceChart — fail those gates when measured. Extending the on-chain six to eight slots passes everything.

#2a78d6 #eb6834 #1baf7a #eda100 #e87ba4 #008300 #4a3aa7 #e34948

Recommendation: promote it to a shared token file; retire the two that fail.

A stylesheet is the prerequisite, not a preference

Dark mode, responsive layout and a type scale are not merely missing today — they are impossible. Inline style={{}} objects cannot express a media query or a prefers-color-scheme rule, and 113 of them carry the current design. Nothing else on this page can be built until styling moves into a stylesheet with tokens.

Recommendation: plain CSS with custom properties in app/globals.css. No new dependency, and it immediately styles the screener, whose BEM class names already exist and currently point at nothing.

Build in the order that protects the tests

185 source lines carry a data-testid, and 165 assertions across 55 end-to-end tests select on them. Styling work touches none of those; restructuring work touches all of them. Those are two different risk profiles and should not be done in one step.

Recommendation: tokens and stylesheet first (no test risk) → one pilot route converted end to end → the nav shell → the remaining four routes.
