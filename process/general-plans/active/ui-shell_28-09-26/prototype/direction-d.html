Direction D — Dark Research Surface

A dark, precise shell wrapped around bright analytical panels, built on the owl's own two colours. The futurism comes from geometry, spacing and restraint — there is no glow, no gradient and no neon anywhere on this page.

PROPOSAL Nothing is merged and no application code has changed. This is a standalone mock-up; web/ is byte-identical to origin/main and the verified baseline — 193 unit tests, 55 end-to-end tests, tsc exit 0 — is untouched.

Identity

The owl, and what it has to survive

The supplied artwork is a 1024 px raster on a baked white background. It cannot sit on a dark shell, and it cannot be a 16 px favicon. Redrawn as vector, it can do both — and its two colours become the whole palette.

The navy cannot go on the dark shell

Measured, not guessed: brand navy #32425a on the shell ground is 1.89:1, well under the 3:1 a graphic needs. On white it is 10.18:1. So the mark inverts — body to light ink on dark, and sage lifts from #657b5b (4.15:1) to #8aa37d (6.96:1). Same drawing, two colourways, both legible.

Why redraw rather than crop

The file is a JPEG with a .png extension — which is why it would not decode when sent inline. It has no alpha, so there is no transparent version to place on dark, and at 16 px the raster's eyes and beak turn to mush. Vector fixes all three at once and makes the colourway a one-line change.

What the mark gives the product

Two forward-facing eyes are binocular vision — depth judged by combining two views that may disagree. That is this app's stated purpose, so the symbol already argues the thesis. The nocturnal reading justifies the dark shell without anyone having to explain it.

One thing I would hold back

The sage green is close in meaning to the mature / healthy green in the uncertainty grammar. Using brand sage in the interface would blur "this is our colour" with "this reading is good". I have kept sage in the mark only and left green to mean one thing. Overridable — see the questions.

The signature move

Dark shell, bright instrument

The shell recedes so the data is the brightest thing on screen. Chart panels stay light and near-neutral — never dark-on-dark — keeping the contrast budget that reading small numbers actually needs.

Data honesty

One grammar, both surfaces

The audit found three unrelated idioms for caveats and an amber that meant two different things. This is a single severity scale, defined once and restated on the light surface so a state reads identically wherever it appears.

The rules that make it a grammar

  • Severity is a rail, never a fill. A 2–3 px left rule or row gutter; the value itself never changes colour, so a number is never harder to read because it is uncertain.
  • A glyph always accompanies the colour — ○ ◐ ● — so the state survives colour-blindness, greyscale and print.
  • Amber means one thing: degraded. Licensing moves to its own neutral outlined badge, which is a fact about the data, not a warning about its quality.
  • Insufficient series are never drawn. They are named beneath the chart with their reason — the current code already produces that sentence, it just has nowhere to put it.
  • Provisional series are drawn dashed with an open endpoint, so a weak read looks weak at a glance without being hidden.

Because the plot surface is light, charts use the light slots. The four used above — blue, orange, aqua, violet — clear every gate including the strict all-pairs run. What the stack actually is

The direction names Svelte 5, LayerChart and Skeleton. Checking the packages turned up two facts that change how much has to move.

svelte5.57.1 — published 18 Sep 2026.
layerchart2.5.0 — peer svelte ^5.0.0. The brief said 2.0.x; 2.5.0 is current. Ships both SVG and Canvas render contexts per component, plus its own svg-vs-canvas benchmark.
@skeletonlabs/skeleton5.0.1 — peer tailwindcss ^4.0.0.
@skeletonlabs/skeleton-svelte5.0.1 — peer svelte ^5.40.0.
@skeletonlabs/skeleton-react5.0.1 — peer react ^18 || ^19. Same version and publish date as the Svelte package.
@sveltejs/kit2.70.3.

Skeleton does not require Svelte

Skeleton 5 ships a first-party React package at the same version. The shell — nav, drawers, buttons, tabs, dialogs — can adopt Skeleton and this dark theme without leaving Next. That decouples the look from the framework move.

LayerChart does require Svelte

It peers on svelte ^5 and is built on @layerstack/svelte-*. There is no React build. Charts are the one part that genuinely has to move — which is exactly where the brief points the pilot.

Tailwind 4 arrives either way

Skeleton peers on it and LayerChart depends on @layerstack/tailwind. That settles the styling mechanism by implication, and supersedes the earlier plain-CSS recommendation.

125 of 193 unit tests are React-bound

They import @testing-library/react and cannot survive a framework change — only be ported. The other 68 are pure TypeScript, and all 55 end-to-end tests are framework-agnostic. The E2E suite is the real safety net for this migration.
