# Collector finish — Stage-0 local feasibility probes

## Hypothesis

The revision-2 browser/relay/profile design can enforce its stated isolation contract on the installed Windows/Edge runtime, and its supporting local mechanisms are available without external services.

## Mechanism Under Test

Plan revision 2, BP3a, BP4a, BP7, BP8, BP13, followed by BP2, BP3b, BP4b, BP11 and blocking BP1. Native Windows inheritable ACLs, mutexes and kill-on-close Job Objects; B2 raw tunnels; twscrape operation substitution; offline provisioning; Chromium pipe/CDP capture, profile mutation and browser network routing.

## Probe Family

- Local group: **1 — Local process / Node script**, using Python/native Windows calls and spawned processes.
- Browser group: **6 — Browser / CDP capture**, with real disposable Edge instances and loopback HTTP/TLS/proxy/UDP fixtures.

## Probe Cost Class

**cheap-local** for BP3a/BP4a/BP7/BP8/BP13; **needs-browser** for BP2/BP3b/BP4b/BP11/BP1. Both gates met. Installed browser reported `Edg/156.0.4314.58`. No shared/user browser profile was opened. No accounts, credentials, live X/Reddit/provider calls, trust-store edits, firewall edits or ACL changes outside the newly created temporary root.

## Probe Method

Read the plan's BP definitions and A5–A17 before probing. Initial cheap-local group ran before the browser group. Follow-up local probes filled identity-binding, abandoned-mutex and denial-guard coverage after the first browser run; follow-up browser runs isolated the failed resolver/bypass/WebRTC assumptions and CDP bounds.

`browser.py` ran four iterations: initial contract flags, resolver exclusion, corrected WebRTC switch, and explicit CDP buffer bounds. Successful pipe/job/ACL setup was not repeated in the later iterations. The relay mapped the allowed authority to a synthetic numeric upstream CONNECT, and the fake upstream mapped that numeric token to a loopback TLS listener. It never dialed the numeric public token.

The test-only certificate was generated by OpenSSL with SANs for the fixture names/loopback and accepted using its specific SPKI hash. No blanket CDP certificate override and no trust-store installation. That tests original SNI and encrypted byte forwarding, not production CA validation.

## Verdict

**NOT-VIABLE overall, against revision 2 as written.** BP1 is blocking. BP3b independently contradicts the profile ACL contract. BP13 retains a native-denial evidence gap. Corrected local relay settings are promising evidence, not a blanket no-leaks certification or authorization to unblock S-Relay.

## Resulting Design Constraint

- **What this licenses:** use the proved Windows mutex/job/pipe mechanisms, B2 raw tunnel primitives, twscrape unit-boundary operation update, and bounded CDP capture in the stated tested scopes.
- **What this forbids:** shipping A5/A8's empty bypass/incorrect WebRTC switch, claiming a root ACL guarantees unchanged descendant ACLs, or treating a Python audit hook as native browser/curl network isolation.
- **What remains uncertain (known-gap):** non-loopback IP/link-local browser traffic, OS-wide DNS/socket completeness, compressed/streaming CDP extremes, production proxy TLS/admission mutation, and the security meaning of Edge's added capability ACEs. Keep browser route/profile slices blocked until the plan absorbs the findings and the remaining gate is explicitly resolved.

## BP3a — Inheritable private directory ACL

**Hypothesis:** A protected owner-only OICI root secures nested objects at creation; B2's file-oriented policy is insufficient for Chromium trees.

**Method:** Native `ConvertStringSecurityDescriptorToSecurityDescriptorW` plus `CreateDirectoryW`, using `O:<actual-token-SID>D:P(A;OICI;FA;;;<actual-token-SID>)`. Create a nested directory/file normally. Inspect with existing `inspect_windows_acl`. Separately use existing `_windows_create(..., directory=True)` and create its child.

**Evidence:**

```text
OICI root: protected=True; owner-only full-control ACE, inherited=False
nested directory: protected=False; owner-only full-control ACE, inherited=True
nested file: protected=False; owner-only full-control ACE, inherited=True
B2-created root's child: protected=False; explicit owner + SYSTEM + logon-session ACEs
logon-session rights: 1179817
```

**Verdict:** **VIABLE** for native inheritable secure creation; the comparison confirms B2's creation policy is not a drop-in tree policy.

**Design constraint:** Licenses protected root plus restrictive inherited descendants. Forbids requiring `SE_DACL_PROTECTED` on every descendant: inheritance deliberately leaves that bit false. Verify effective principals/rights, owner, inheritance source and inheritable root ACE flags instead. The existing `Acl` projection reports inherited status but does not expose OI/CI flags, so profile verification must not assume that projection alone proves propagation. Does not establish that Edge leaves those ACLs unchanged; BP3b disproves that.

## BP4a — Machine-wide mutex and launcher death

**Hypothesis:** A named Global mutex is independent of cache paths, and kill-on-close Job Object ownership survives the desired launcher-death threat model.

**Method:** Two fresh processes in different temporary cache directories contend for the same `Global\\...` test mutex with timeout zero. Kill an owning process and acquire its abandoned mutex. Launch a suspended Python child, assign it to a non-inherited Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, resume it, let it spawn a grandchild, then force-kill the launcher. Separately exercise a synthetic recorded PID's native creation time, refuse a mismatching record and terminate the matching disposable process.

**Evidence:**

```json
{"first":0,"cache_contention":[258,258],"released":0,
 "tree_before":[true,true],"tree_after":[false,false],
 "abandoned_mutex_wait":128,"creation_mismatch_refused":true,
 "matching_orphan_before":true,"matching_orphan_after":false}
```

**Verdict:** **VIABLE** for the local native mechanisms.

**Design constraint:** Acquire with timeout zero; handle both normal and abandoned successful acquisition explicitly. Create suspended, assign to Job Object, then resume—do not race assignment against child spawning. Do not inherit the job handle into children. Orphan recovery must verify PID creation time and a trusted profile record before termination. The synthetic PID probe is not evidence that a production profile-ownership/orphan scanner already exists, and no cross-login-session run was performed.

## BP7 — B2 raw tunnel reuse

**Hypothesis:** Existing `resolve_public`, `BoundBackend` and `ConnectFrame` can support the relay without a second transport convention.

**Method:** Import the existing modules read-only. Drive `BoundBackend` against a loopback fake upstream, bind `allowed.invalid:443` to synthetic numeric `93.184.216.34:443`, send CONNECT, then exchange raw `PING`. Exercise public/private literal resolution locally, without DNS.

**Evidence:**

```text
wire: CONNECT 93.184.216.34:443 HTTP/1.1
reply: HTTP/1.1 200 OK
raw post-CONNECT echo: PING
127.0.0.1, 169.254.169.254, ::1: ProxyFailure
93.184.216.34: accepted as public literal
```

**Verdict:** **VIABLE** for the raw tunnel interface.

**Design constraint:** Reuse `BoundBackend`'s pinned upstream dial and `ConnectFrame`'s authority replacement. The relay must still perform strict authority validation and public-address selection before using the frame. No real connection to the public numeric token was made. This probe does not prove authenticated HTTPS upstream TLS, DNS races, admission expiry, revocation or half-close/backpressure behavior. BP1 used a minimal independent relay fixture; it is not a production relay integration test.

## BP8 — Operation substitution at the identity boundary

**Hypothesis:** Setting `twscrape.api.OP_SearchTimeline` before a new unit takes effect on its next `search_raw` while the identity adapter remains bound.

**Method:** First exercise the installed library's async generator boundary. Then instantiate real `TwscrapeReader` and real `IdentityAdapter`, use a disposable DB path, replace only `_gql_items` with a loopback fake-X HTTP response generator, and issue page-zero units after assigning two synthetic operation IDs. Observe both the URL and adapter context from inside the generator.

**Evidence:**

```json
{"loopback_paths":["/ProbeA/SearchTimeline","/ProbeB/SearchTimeline"],
 "identity_labels":["probe","probe"]}
```

**Verdict:** **VIABLE** for unit-boundary rebinding.

**Design constraint:** Update the module variable before starting a fresh unit/generator; `search_raw` captures `op` on generator execution. Do not assume an already-running generator changes its operation, and do not mutate a process-global operation concurrently across unrelated units without serialization. The probe exercised real reader/adapter binding but intentionally did not install account/proxy runtime hooks or validate a live operation ID.

## BP13 — Offline provisioning and spawned denial guard

**Hypothesis:** The locked local environment and synthetic certificate tool are available offline, and a spawned fixture guard can stop unintended network use.

**Method:** Run frozen/offline uv with the xreader group; import twscrape and websockets; discover/run OpenSSL. In a fresh Python process install an audit hook denying non-loopback `socket.getaddrinfo` and `socket.connect`, then attempt a `.test` lookup and a numeric non-loopback connection. Both are denied before system networking.

**Evidence:**

```text
imports_ok
C:\Program Files\Git\usr\bin\openssl.EXE
OpenSSL 3.5.5 27 Jan 2026 (Library: OpenSSL 3.5.5 27 Jan 2026)
spawned guard: dns_denied
spawned guard: connect_denied
```

**Verdict:** **INCONCLUSIVE** for the full network-denial claim; offline provisioning and Python-hook denial are individually viable.

**Design constraint:** Licenses this already-provisioned machine's offline execution, not an uncached fresh installation. The denial hook must be installed in each Python child before imports that may network. It does not intercept native curl/Chromium socket calls or arbitrary grandchildren: forbid calling it a universal sandbox. Native browser probes instead used local proxy rejection and resolver rules, with the specific BP1 gaps stated below. No disposable container or machine-wide deny mechanism was introduced.

## BP2 — Python-to-Edge debugging pipe

**Hypothesis:** Edge supports pipe CDP from Python on Windows, with a GUID websocket fallback when needed.

**Method:** Create two inheritable anonymous pipes using Python, pass the native handles using `--remote-debugging-pipe --remote-debugging-io-pipes=<input-handle>,<output-handle>`, send a NUL-terminated `Browser.getVersion` command, and read its response. Separately launch a fresh protected profile with `--remote-debugging-port=0` and read/connect to its `DevToolsActivePort` endpoint.

**Evidence:**

```json
{"pipe_reply":true,"pipe_endpoint_file":false,
 "fallback":{"guid_path":true,"inside_profile":true},
 "browser":"Edg/156.0.4314.58"}
```

**Verdict:** **VIABLE**.

**Design constraint:** Prefer native-handle pipe transport with NUL frame delimiters. Do not use Unix fd-3/fd-4 assumptions on Windows. The probe used broad handle inheritance for a disposable process; production must restrict inherited handles to the two intended pipe ends and close unused ends promptly. No `--remote-allow-origins` was needed for fallback. GUID obscurity is not authorization; the same-user threat boundary remains. Long-lived concurrent pipe framing/flow control was not exercised.

## BP3b — Browser-created ACLs and drift detection

**Hypothesis:** Real Edge descendants remain limited to the owner's inherited permissions, and a post-session sweep detects deviations.

**Method:** Launch Edge under an OICI owner-only root; terminate the disposable session; inspect `Local State`, `Default`, `Default/Network`, and `Default/Network/Cookies`. Add a synthetic Everyone-read ACE only to a temporary sentinel file and inspect it to demonstrate drift detection.

**Evidence:**

```text
root protected=True
Local State: owner-only inherited ACE
Default: owner-only inherited ACE
Default/Network: two additional explicit allow ACEs for:
S-1-15-3-1024-3239966617-1410756637-3494353204-65451782-2225605771-3526040376-1730753648-3419555762
rights: 1245631 and 3758161920
Default/Network/Cookies: additional inherited allow ACE for the same SID, rights=1245631
owner_only=False; inherited=True; synthetic Everyone drift detected=True
```

`Default/Preferences` and legacy `Default/Cookies` were absent in this force-terminated profile and were not asserted protected. No cookie values were read.

**Verdict:** **NOT-VIABLE** for revision 2's strict descendant principal contract. The sweep can detect drift, but normal browser startup already produces it.

**Design constraint:** Do not claim owner/SYSTEM-only descendants merely from secure root creation. Keep refusal on unknown principal drift. Investigate and explicitly threat-model the browser-added capability SID and its required rights before deciding whether a narrowly verified exception is acceptable. Do not whitelist all capability SIDs, disable the network sandbox, or repair an existing profile's ACL to make the test pass. If the exact strict policy remains mandatory, this Edge profile implementation is incompatible and must stay blocked. Complete sensitive-file sweeps must handle both absent and present profile files and inspect Network itself, not just top-level children.

## BP4b — Real browser tree termination

**Hypothesis:** Force-killing the launcher closes its Job Object and terminates the real Edge process tree.

**Method:** A separate Python launcher creates a non-inherited kill-on-close Job Object; it creates Edge suspended, assigns it, and resumes it. The probe connects by CDP, enumerates `SystemInfo.getProcessInfo`, force-kills the launcher and checks every reported PID with native process-exit queries.

**Evidence:**

```json
{"reported_processes":6,
 "types":["browser","renderer","renderer","GPU",
          "network.mojom.NetworkService","storage.mojom.StorageService"],
 "alive_after":[]}
```

**Verdict:** **VIABLE** for this Edge launch/process topology.

**Design constraint:** Use suspended creation/assignment and a launcher-owned non-inherited handle. Never kill all `msedge.exe` instances; target only the owned job/tree. This establishes the six reported processes, not all possible future browser helper types or scheduled-task/locked-session behavior. No existing user Edge process was touched.

## BP11 — Bounded CDP capture against a local SPA

**Hypothesis:** Subscribe before navigation, correlate by request ID through `loadingFinished`, obtain response bodies, recognize redirects/cache/failures, and enforce capture limits.

**Method:** Attach a flattened target session, enable Network/Page before navigation, and load a synthetic HTTPS fixture issuing JSON fetches, a 302 to a rejected host, a closed response, repeated cacheable fetches, a 128-KiB body, a service worker and WebSockets. Correlate response events with completed request IDs before `Network.getResponseBody`. Repeat with `Network.enable` limits `maxResourceBufferSize=65536` and `maxTotalBufferSize=262144`; websocket client frame ceiling was 1 MiB. This deliberately tests capture mechanics, not production navigation/evaluate policy.

**Evidence:**

```text
responses=7; loadingFinished=7; redirect_events=1; failures=5
cache_events=0; response.fromDiskCache=true count=1
WebSocket handshake responses=1
/api body=30 bytes; /cache body=2 bytes
without native bounds: /large body=131072 bytes (application rejects as oversized)
with native bounds: /large getResponseBody returns -32000:
  Request content was evicted from inspector cache
failure reasons include ERR_EMPTY_RESPONSE and ERR_TUNNEL_CONNECTION_FAILED
```

A separate intermediate pass rejected the known oversized Content-Length before asking for its body. The final bound pass intentionally asked for it to demonstrate native eviction instead of materializing the large body.

**Verdict:** **VIABLE** for the tested capture/buffering mechanisms.

**Design constraint:** Permit explicit bounded Network.enable parameters in the CDP chokepoint; empty params alone are not a bounded-capture implementation. Correlate session/request/redirect lifecycle, and fetch only after loadingFinished. Handle inspector-cache eviction as an honest bounded-capture failure, never empty-success. Check `response.fromDiskCache`; `requestServedFromCache` alone missed the observed cache hit. Bound frames, pending requests and retained event metadata separately; the probe's temporary event list is not a production bounded collector. Unknown-length/compressed bodies, resource-flood stress and long-running session limits remain unproved.

## BP1 — Blocking CONNECT-relay leak probe

**Hypothesis:** Revision 2's relay/flags prevent direct connections while preserving numeric CONNECT routing and original TLS SNI across hostile browser traffic and proxy outage.

**Method:** Browser → loopback CONNECT-only relay → loopback fake upstream proxy → loopback TLS origin. Relay accepts exactly `CONNECT allowed.test:443 HTTP/1.1`; all other authorities/methods are refused before upstream dial. Upstream accepts only `CONNECT 93.184.216.34:443 HTTP/1.1`, then connects to the local TLS listener. Hostile page requests an off-allowlist redirect, off-allowlist fetch/WebSocket/service-worker fetch, loopback IP-literal and localhost HTTPS URLs on a sentinel port, and STUN at a loopback UDP sentinel. The allowed WebSocket completes a real HTTP 101 handshake. Relay outage closes its listener and active browser-side tunnels before another navigation.

**Evidence — initial revision-2 resolver configuration:**

```text
--host-resolver-rules=MAP * ~NOTFOUND
relay accepted requests=0; upstream CONNECTs=0; origin hits=0
```

This first run was not counted as a successful leak test: the fixture never loaded. Adding only `EXCLUDE 127.0.0.1` made allowed navigation and fixture execution work. The initial run did not preserve its first navigation error, so no more specific error code is claimed for it.

**Evidence — resolver corrected, original empty bypass / original WebRTC flag:**

```text
--proxy-bypass-list=
--force-webrtc-ip-handling-policy=disable_non_proxied_udp
DIRECT sentinel: GET /ip HTTP/1.1
DIRECT loopback UDP sentinel: 4 packets
upstream: 10 numeric CONNECTs; original TLS SNI: allowed.test
```

**Evidence — explicit removal of implicit loopback bypass, original WebRTC flag:**

```text
--proxy-bypass-list=<-loopback>
direct HTTPS sentinel hits=0
relay refused CONNECT 127.0.0.1:<sentinel-port> and CONNECT localhost:<sentinel-port>
DIRECT loopback UDP sentinel: 4 packets
```

**Evidence — corrected WebRTC switch and explicit bypass removal:**

```text
--host-resolver-rules=MAP * ~NOTFOUND, EXCLUDE 127.0.0.1
--proxy-bypass-list=<-loopback>
--webrtc-ip-handling-policy=disable_non_proxied_udp
DIRECT HTTPS sentinel hits=0; DIRECT UDP sentinel packets=0
upstream: 10 × CONNECT 93.184.216.34:443 HTTP/1.1
TLS SNI: allowed.test
origin paths: /, /api, /redirect, /fail, /large, /cache, /ws, /sw.js, /sw-signal, /favicon.ico
relay refused off.test:443 four times; no off-allowlist upstream CONNECT
proxy outage: net::ERR_PROXY_CONNECTION_FAILED
outage new origin hits=0; outage new direct HTTPS sentinel hits=0
```

Edge also attempted background Microsoft/Bing/Office/SmartScreen authorities despite the background-disable flags. These attempts reached the **local relay and were rejected**; they were not forwarded to those services. Raw request query strings are deliberately omitted here. Examples: `edge.microsoft.com`, `www.bing.com`, `nav-edge.smartscreen.microsoft.com`, `mss.office.com`, `substrate.office.com`. Background-disable flags are not an egress policy.

**Verdict:** **NOT-VIABLE** for the plan as written. The direct HTTPS and UDP bypasses are observed failures, not merely missing evidence. The corrected configuration passed the exercised local sentinels but remains a constrained candidate, not a complete isolation proof.

**Design constraint:**

- **Licenses:** the local relay topology, strict authority rejection before any dial, numeric upstream CONNECT and preserved origin SNI; corrected switches for a further bounded validation run.
- **Forbids:** an empty bypass list as a claim of no Chromium implicit bypass; `--force-webrtc-ip-handling-policy` as an effective policy on this Edge version; assuming broad resolver failure leaves a loopback proxy usable; using “no direct fallback” to cover untested protocols or addresses; treating WebSocket/SW page checks as substitutes for relay enforcement.
- **Required plan adjustments:** replace empty bypass with explicit `--proxy-bypass-list=<-loopback>`; replace the ineffective WebRTC switch with the observed `--webrtc-ip-handling-policy=disable_non_proxied_udp`; include the narrowly scoped literal relay exclusion in resolver rules; keep QUIC disabled; make browser-version-specific negative sentinel probes an admission gate; redact/bound refusal metadata and do not relax the allowlist for browser background traffic.
- **Known gaps:** the no-external-network gate excluded actual non-loopback IP-literal/link-local URL/STUN attempts. Host-resolver mapping does not constrain numeric IP sockets, as the loopback leak demonstrates. No OS-wide packet capture or native all-process socket interception was used, so absence of every possible external packet is not established. Fixture/network handlers only dialed loopback; DNS for fixture authorities was never delegated externally. Corrected settings produced zero observed local leaks, not a universal no-external-traffic theorem. Native packet-level/non-loopback containment evidence is still required before unblocking the absolute claim. Production upstream TLS trust, expiry/revision/quarantine teardown, malformed authority matrices and real account behavior were not tested by this feasibility fixture.
